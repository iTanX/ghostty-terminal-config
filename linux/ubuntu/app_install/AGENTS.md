# 软件安装脚本维护约定

## 目标与目录

本目录用于维护 Ubuntu 下当前用户的软件安装与配置，不是某个软件的专用安装项目。目录位于仓库的 `linux/ubuntu/app_install/` 下，不要自行迁移到用户主目录或新建其他项目目录。

```text
app_install/
├── AGENTS.md          # 本目录及子目录的维护约定
├── install.sh         # 自动发现软件脚本的通用入口
└── apps/
    └── snipaste.sh    # 每个软件使用独立脚本
```

- 通用入口只负责发现、执行软件脚本和报告结果，不得包含软件名称、下载地址、安装逻辑或软件配置。
- 自动遍历 `apps/` 第一层的 `*.sh` 普通文件，按文件名字节顺序串行执行；不要求专属脚本具有可执行权限。
- 入口通过独立的 `bash` 进程运行各专属脚本，不使用 `source`，避免变量、函数、trap 和 `exit` 相互影响。
- 任一软件脚本失败时停止后续安装，保留并报告其退出码；没有脚本时打印提示并正常结束。
- 新增软件只需添加 `apps/<软件名>.sh`，不得为此修改入口。需要指定执行顺序时可使用数字文件名前缀。
- 不要在 `apps/` 下放辅助 `.sh` 文件，否则会被当作安装脚本执行。尚无复用需求时不新增公共库或其他框架。

## 软件专属脚本

- 每个软件的下载、安装、菜单、快捷键和其他配置都放在其独立脚本中，支持单独执行。
- 使用 Bash、`set -euo pipefail`，添加必要的简体中文注释与状态提示。
- 必须写清楚安装流程，使用 `1`、`1.1`、`1.2`、`2`、`2.1` 这样的层级序号注释：主流程标明大步骤，对应函数内标明子步骤。编号按实际执行顺序组织，说明该步骤做什么及必要原因，不要逐行翻译代码。
- 专属脚本的流程注释应覆盖：运行身份与依赖检查、平台检查、同版本复用、下载安装包、解包校验、备份替换、桌面集成、专属配置、人工回退和完成提示；不适用的步骤不必添加。入口也应注明身份检查、自动发现、执行与失败处理的层级步骤。
- 使用脚本自身路径定位目录，不依赖调用者当前工作目录；引用路径变量，兼容路径包含空格。
- 默认按当前用户安装，不使用 `sudo`，并拒绝以 root 身份运行。
- 程序默认放在 `${HOME}/.local/opt/<软件名>/`，菜单入口放在 `${XDG_DATA_HOME:-${HOME}/.local/share}/applications/`；不要把下载文件夹当作软件运行目录。
- 下载包放在独立的新临时目录内；解包内容不得与脚本混放。处理包文件的 Python 使用 `python3 -I`，不要从下载内容所在目录启动 Python。
- 使用 HTTPS 下载并检查失败；先完成解包和基本校验，再替换正式安装目录。替换已有目录前保留备份，不得直接删除用户配置。
- 保证重复执行不重复安装同版本、不重复注册快捷键、不覆盖无关配置；仅变更当前软件所需内容。
- 配置失败但不影响安装完成时，在专属脚本末尾清晰打印人工步骤，包括名称、完整命令和按键；安装失败必须返回非零退出码，不得打印成功。

## 当前 Snipaste 要求

- 版本：`2.11.3`，平台：Linux x86_64。
- 下载地址：`https://download.snipaste.com/archives/Snipaste-2.11.3-x86_64.AppImage`。
- 解包运行 AppImage，以便不依赖系统 FUSE 2；启动入口为安装目录中的 `app/AppRun`。
- 创建应用菜单入口。
- 仅配置截图命令 `AppRun snip`，快捷键为 **Ctrl + F1**；不添加贴图快捷键或开机自启。
- 在 GNOME 下尝试自动配置系统自定义快捷键，复用同命令的已有条目；保留其他快捷键，发现冲突不得抢占。
- 非 GNOME、缺少组件、无法写入或存在冲突时，在脚本末尾打印手动配置步骤。
- 提醒用户必须先启动 Snipaste 并保持后台运行，截图命令才会生效。

## 验证

- 修改后对入口及全部软件脚本运行 `bash -n`。
- 验证入口能自动发现新增脚本、按约定顺序执行、在任意工作目录运行，以及失败后停止并保留退出码。
- 使用隔离目录验证软件安装和重复执行；快捷键测试使用隔离的 GSettings 后端，避免改动真实桌面配置。
- 安装包未改变时可复用现有包进行解包测试；如只验证了下载地址可访问，应如实说明，没有重新测试网络下载。
- 完成拆分后不保留旧的单文件安装入口，避免用户使用到过期版本。
