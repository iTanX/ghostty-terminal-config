# GNOME 扩展设置备份与恢复

原始备份时间：2026-11-15 19:54:54（本机时间）。源环境：GNOME Shell 48.7。

## 备份范围

仅保留当时已启用且有显式保存配置的 6 个扩展。不备份使用默认值、没有独立设置或已禁用的扩展，恢复时也不会修改它们。

| 扩展 | 版本 | dconf 路径 |
| --- | --- | --- |
| Dash to Panel | 74 | `/org/gnome/shell/extensions/dash-to-panel/` |
| Tiling Assistant | 56 | `/org/gnome/shell/extensions/tiling-assistant/` |
| Clipboard Indicator | 72 | `/org/gnome/shell/extensions/clipboard-indicator/` |
| Blur my Shell | 78 | `/org/gnome/shell/extensions/blur-my-shell/`，包含所有子路径 |
| Caffeine | 61 | `/org/gnome/shell/extensions/caffeine/` |
| Status Tray | 34 | `/org/gnome/shell/extensions/status-tray/` |

这些路径是 dconf 数据库内部路径，不是磁盘目录。

GSettings/dconf 导出的是显式保存的值，不会把扩展的所有默认值展开保存。恢复这 6 个扩展时，先清除各自路径下的设置，再导入备份，确保后来新增的设置不会残留。未包含在备份中的项目使用安装版本的默认值，因此尽量使用与原环境相同或兼容的 GNOME 和扩展版本。

本备份不包含扩展程序、Tiling Assistant 的 `layouts.json` 和窗口会话文件、剪贴板历史与收藏、主题及自定义图标文件、其他 GNOME 设置。

## 目录内容

- `settings/`：6 个扩展的 dconf 文本导出文件，均非空。
- `settings.tsv`：这 6 个扩展的 UUID、dconf 路径和备份文件对应关系，以制表符分隔。
- `enabled-extensions.txt`：仅包含备份中这 6 个扩展的 UUID，用于可选重新启用。
- `backup-info.json`：原始备份时间、GNOME 版本、扩展名称和版本等信息。
- `restore.sh`：恢复脚本。
- `恢复说明.md`：本文档。

保留整个目录，移动或改名后仍可使用脚本。

## 使用脚本恢复

在需要恢复的用户自己的 GNOME 桌面会话中运行，不要使用 `sudo`。先安装所需扩展；本备份不负责安装扩展。建议先关闭扩展的设置窗口，避免恢复时同时编辑配置。

以下脚本和手动恢复命令均适用于 Debian、Arch 等发行版的 GNOME 桌面，按系统已有 `bash` 和 `dconf` 使用。

进入本备份目录后执行：

```bash
bash ./restore.sh
```

默认只恢复表中 6 个 dconf 路径下的设置，不改变扩展的启用／禁用状态。

如需同时启用备份中的 6 个扩展：

```bash
bash ./restore.sh --enable
```

此选项还需要 `gnome-extensions` 命令，并会在恢复前检查这 6 个扩展是否已安装且能被当前 GNOME 会话识别。它只启用这 6 个扩展，不修改其他扩展的开关，也不改 GNOME 扩展总开关。若总开关已关闭，请在“扩展”应用中打开。新安装扩展如果暂时不能识别，可注销后重新登录再运行。

脚本会先把目标路径当前的设置保存到本目录下新建的 `恢复前设置-时间-随机字符/` 中，全部导出成功后才开始覆盖。若恢复过程报错，可能已恢复部分扩展；脚本不会自动回滚，可按下文方法导回恢复前的设置。

恢复完成后，如桌面显示未更新，注销并重新登录。

## 手动恢复

以下命令都在本备份目录中执行。路径末尾的 `/` 不能省略。

### 只恢复一个扩展

以 Dash to Panel 为例，先保存它当前的设置，然后清除旧值并导入备份：

```bash
# 保存恢复前的配置，使用临时文件避免覆盖已有文件。
previous_file="$(mktemp ./dash-to-panel-恢复前-XXXXXX.dconf)"
dconf dump /org/gnome/shell/extensions/dash-to-panel/ > "$previous_file"
printf '恢复前的设置：%s\n' "$previous_file"

# 清除该扩展当前的显式设置，再加载备份。
dconf reset -f /org/gnome/shell/extensions/dash-to-panel/
dconf load /org/gnome/shell/extensions/dash-to-panel/ \
  < settings/dash-to-panel@jderose9.github.com.dconf
```

其他扩展按上表替换路径，并使用 `settings/` 下对应 UUID 的 `.dconf` 文件。

先 reset 才能清除后来新增的值，让备份中未显式保存的项目回到默认值；单独 load 只会合并设置。请只对表中精确的扩展路径执行 reset。

### 批量手动恢复全部设置

在本备份目录打开终端，启动 Bash：

```bash
bash
```

然后执行以下代码。它先保存所有目标路径的当前值，再清除并导入设置：

```bash
(
    set -euo pipefail
    umask 077
    previous_dir="$(mktemp -d ./手动恢复前设置-XXXXXX)"
    mkdir "$previous_dir/settings"
    cp settings.tsv "$previous_dir/settings.tsv"

    while IFS=$'\t' read -r uuid path file; do
        dconf dump "$path" > "$previous_dir/$file"
    done < settings.tsv
    printf '恢复前的设置：%s\n' "$previous_dir"

    while IFS=$'\t' read -r uuid path file; do
        dconf reset -f "$path"
        dconf load "$path" < "$file"
        printf '已恢复：%s\n' "$uuid"
    done < settings.tsv
)
```

如需手动启用这 6 个扩展，在确认已安装后执行：

```bash
while IFS= read -r uuid; do
    gnome-extensions enable "$uuid" || break
done < enabled-extensions.txt
```

### 撤销一次设置恢复

进入那次恢复生成的 `恢复前设置-…/` 或 `手动恢复前设置-…/` 目录，在 Bash 中执行下面的代码，把恢复前保存的设置导回。恢复前的设置可能为空，因此这里保留空文件判断：

```bash
(
    set -euo pipefail
    while IFS=$'\t' read -r uuid path file; do
        dconf reset -f "$path"
        if [[ -s "$file" ]]; then
            dconf load "$path" < "$file"
        fi
        printf '已导回恢复前设置：%s\n' "$uuid"
    done < settings.tsv
)
```

这只撤销设置值的变化，不撤销 `--enable` 对扩展开关的修改。
